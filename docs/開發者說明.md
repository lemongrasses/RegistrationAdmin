# 開發者說明

## 環境

- .NET 10 SDK（`global.json` 指定 10.0.100，允許 latestFeature）
- Windows 10 22H2 x64 / Windows 11 x64（WPF 與 DPAPI 只能在 Windows 執行；Core、Export 與單元測試可跨平台）
- 套件版本集中在 `Directory.Packages.props`（Central Package Management）。版本為最低需求，第一次 restore 後產生 `packages.lock.json`，請提交以鎖定實際版本。

## 架構原則

- ViewModel 不直接呼叫 Google API、不組 A1 range；一律透過 `RegistrationWorkspace`（Core）與 `IRegistrationStore`。
- `IRegistrationStore` 沒有任何寫入原始回應的方法；`SourceResponseReader` 只有讀取方法。
- 程式碼只使用 `LogicalFields` 的邏輯欄位名稱；中文題目標題只存在 `_FieldMap`。
- 寫入一律 `ValueInputOption = RAW`，`01234567` 等字串不會被 Sheets 轉成數字。
- 冪等的 `values.batchUpdate` 會在 429／5xx 時退避重試；非冪等的 `append` 不重試，避免逾時重送造成重複列（萬一重複，`ADMIN_DUPLICATE_KEY` 問題會提示）。
- 日誌只寫數量、代碼與報名編號；`RedactingTextFormatter` 再以 `Redactor` 遮蔽 Email、8 位以上數字、身分證字號與 token。
- 介面層（`RegistrationAdmin.App`）：`Presentation/` 放不依賴 WPF 的畫面邏輯（待處理判斷、狀態色調、下一步按鈕、使用者文案、欄位中文名），`ViewModels/` 放畫面狀態，`Themes/Theme.xaml` 是唯一的樣式來源（色彩、按鈕、輸入框、表格、狀態標籤）。改版規格見 `docs/ui-reference/claude-ui-redesign-brief.md`。
- 內建使用手冊：`docs/manual/使用手冊.md` 以 EmbeddedResource 隨程式編譯，`images/*.png` 以 WPF Resource 隨附；`UserManual` 提供章節與全文篩選，`HelpWindow` 用原生 WPF 顯示文字、表格與截圖。修改手冊後重新建置即可更新內建說明，不需另裝瀏覽器控制項。`HelpCommands.Open` 以章節編號跳轉，F1 依目前頁面選擇章節；說明視窗不切換主畫面的導航。
- 詳細頁的「下一步」按鈕（`FlowActions`）只依序套用 `StatusTransitions` 允許的轉換；任何一步驗證失敗就整個還原工作副本。一般模式的文字不得出現 `_Admin` 等分頁名稱或英文欄名，錯誤一律經 `UserMessages` 轉成中文。

## 與規劃文件的差異（需 Phase 0 確認）

| 項目 | 規劃 | 實作 | 原因 |
|---|---|---|---|
| `_FieldMap` 欄位 | 9 欄 | 多一欄 `option_match` | 表單第 1 題是一題兩個 Checkbox 選項（資料使用、三日全勤），需以選項文字分辨 |
| 狀態轉換 | 9.1 | 另允許「候補→取消」、「已確認→取消」 | 報名者主動退出時需要；不需要可在 `StatusTransitions` 移除 |
| 通過待付款 | — | 套用時若付款狀態為「未通知付款」，自動改為「待付款」 | 同一次人工操作的一部分，不是背景轉換 |
| 可能的關聯變更 | 8.1 | 新來源與 orphan 管理列「時間戳相同」或「Email 相同」即列為待人工重新連結 | 保守做法：寧可請人確認，不靜默新增第二筆 |
| Sheets 429 配額 | 指數退避 | 429 退避拉長到約 90 秒（2→4→8→16→30→30 秒）；附加寫入只在 429 重試 | 每分鐘寫入配額 60 次；連續審核多筆時會觸發 |
| `_Config` | 欄位清單 | 以 key／value 兩欄保存，另加 `registration_no_prefix`、`seat_occupying_statuses` | 方便在試算表直接調整名額規則 |

## 測試

```powershell
dotnet test tests/RegistrationAdmin.Tests
dotnet test tests/RegistrationAdmin.App.Tests   # 畫面狀態與文案（不開啟視窗）
```

單元測試使用規劃 13.1 的固定測試資料（`tests/RegistrationAdmin.Tests/TestData/Fixtures.cs`，`RegistrationAdmin.App.Tests` 共用同一份），Email 一律 `example.test`。

Google 整合測試（只對複製的測試試算表）：

```powershell
.\scripts\integration-test.ps1 -SpreadsheetId <測試試算表ID> -ClientSecretPath config\google-oauth-client.json
```

`-SourceSheetId`（試算表網址 `#gid=` 後的數字）可省略：省略時沿用測試試算表 `_Config` 已記錄的來源工作表（需先用程式初始化過）。整合測試的授權另存在 `%LOCALAPPDATA%\RegistrationAdmin\it-tokens`，第一次會開啟瀏覽器。

### 端對端 UAT 工具（只對複製的測試試算表）

`tools/UatHarness` 是不在方案內、不隨程式發佈的命令列工具，以真實的 Google Sheets store 驅動 `RegistrationWorkspace`：

```powershell
dotnet run --project tools/UatHarness -- seed    <測試試算表ID> <OAuth JSON>   # 寫入規劃 13.1 的虛構回應（A–G、P01–P05）
dotnet run --project tools/UatHarness -- run     <測試試算表ID> <OAuth JSON>   # UAT-02/03/07/08/11/12/13/18/19
dotnet run --project tools/UatHarness -- more    <測試試算表ID> <OAuth JSON>   # UAT-04/05/06/09/10/12/14/15/16/17/19 與 row_version 衝突
dotnet run --project tools/UatHarness -- restore <測試試算表ID> <OAuth JSON>   # 中斷後還原：Email 標題、依時間戳排序、清除碰撞列
```

`more` 會暫時排序、改標題、改值與加碰撞列，每項結束後還原，最後逐欄比對原始回應頁。Sheets API 每分鐘寫入配額為 60 次，整輪約需數分鐘。

## OAuth 用戶端（隨程式發佈）

- 一般使用者不選擇 JSON：程式讀取 exe 旁的 `google-oauth-client.json`（Desktop app 類型；Google 視此類 client secret 為非機密）。
- 開發時把 JSON 放在 `config\google-oauth-client.json`，`RegistrationAdmin.App.csproj` 會在建置／發佈時複製到輸出資料夾；檔案存在 `.gitignore`，不進版控。
- 「設定 → 進階（管理員）」可指定自訂 JSON，優先於隨附檔案（`LocalSettings.EffectiveClientSecretPath`）。
- 登入範圍：`spreadsheets`、`openid`、`email`，每次啟動會無瀏覽器恢復授權並向 Google 確認帳號。
- `GoogleSpreadsheetPicker` 使用 Google 官方桌面 Picker (`trigger_onepick=true`)，獨立 `drive.file` scope、PKCE 與隨機 state；回呼只監聽隨機 loopback 連接埠。選擇器 token 僅存在記憶體，不覆蓋 DPAPI 保存的 Sheets token。Drive API 的 `about.user.emailAddress` 與 `files.capabilities.canEdit` 用來確認相同帳號、Google 試算表類型與編輯權限。
- 同一 Cloud 專案需啟用 Google Picker API 與 Google Drive API；不需 API key、WebView 或 Web OAuth client。選取只填入設定，需按「連線試算表」才開始既有連線流程。官方說明：https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker

## 發行

`scripts/publish.ps1` 產出 win-x64 self-contained 單一執行檔，再用 [Velopack](https://velopack.io)（`vpk`，本機工具，見 `dotnet-tools.json`）打包成安裝程式與更新套件：

- 安裝：`artifacts/installer/RegistrationAdminApp-win-Setup.exe`，per-user 安裝到 `%LOCALAPPDATA%\RegistrationAdminApp`（packId `RegistrationAdminApp`），建立桌面與開始功能表捷徑，並登錄到「應用程式」可解除安裝。
- 使用者資料（`settings.json`、`tokens\`、`logs\`）在 `%LOCALAPPDATA%\RegistrationAdmin`，刻意與安裝目錄分開，更新與解除安裝都不會刪除。
- 更新：`Program.Main` 先呼叫 `VelopackApp.Build().Run()`；`UpdateViewModel` 啟動後背景檢查並下載，左下角顯示「重新啟動並更新」。免安裝版（zip）與 `dotnet run` 不檢查更新。
- 更新來源只有一個設定值：`config/update-feed.txt`（資料夾路徑、`\server\share` 或 `https://github.com/<org>/<repo>`），打包時寫進安裝目錄的 `update-feed.txt`。資料夾來源由 `publish.ps1` 自動 `vpk download/upload local`，因此能產生差異更新檔。
- OAuth 用戶端：`config/google-oauth-client.json`，或 `config` 下唯一的 `client_secret_*.json`，打包時以 `google-oauth-client.json` 放進安裝目錄；兩者都在 `.gitignore`。
- 尚未簽章。取得組織程式碼簽章憑證後在 `vpk pack` 加 `--signParams`。
