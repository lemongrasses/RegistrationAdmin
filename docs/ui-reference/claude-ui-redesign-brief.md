# 給 Claude 的 RegistrationAdmin UI 改版需求書

## 目標

只重新設計 WPF 畫面與操作流程。保留目前已可工作的 Core、Google Sheets 同步、原始回應唯讀、匯出與驗證邏輯；不要趁 UI 改版重寫資料層或擴充成完整活動管理平台。

主要使用者是不熟悉電腦與資料庫的一般行政人員。介面應讓使用者一眼知道「現在有哪些事情要處理」以及「下一步按哪裡」。

## 優先設計原則

1. 工作優先，不以資料表結構為中心。
2. 預設顯示日常需要，技術設定漸進揭露。
3. 一個畫面只保留一個主要動作。
4. 原始表單答案明確標示「原始資料・唯讀」。
5. 可編輯的後台欄位集中在同一區，不與原始答案混排。
6. 儲存前顯示將改變哪些狀態；儲存後顯示明確成功訊息與時間。
7. 網路或 Google 錯誤不得顯示 exception、HTTP code 或內部欄名給一般使用者；改成可採取行動的中文。
8. 所有重要功能可用鍵盤完成；焦點順序符合畫面順序。

## 資訊架構

一般模式左側導航固定為：

1. `待處理`：預設首頁。
2. `全部名單`：搜尋、篩選與排序。
3. `匯出`：使用預設範本匯出目前篩選結果。
4. `設定`：連線狀態；進階設定藏在頁面下方。

不要在主導航顯示：

- `_Config`、`_Admin`、`_FieldMap`、`_Lookups`、`_ChangeLog`
- source key、fingerprint、row version、profile id、schema version
- OAuth client JSON、Spreadsheet ID、sheetId

這些只允許出現在 `設定 → 進階（管理員）`，並優先使用中文說明。

## 畫面 1：待處理／名單

參考 `01-general-mode.svg`。

- 頁首顯示活動名稱；次要文字顯示日期、名額及最後同步時間。
- 第一列只放 4 張摘要卡：全部、待審核、待付款、已確認。
- 主要清單上方放一個大型搜尋框，可搜尋姓名、Email、電話、單位、報名編號。
- 常用篩選改成單擊籤：`全部`、`待處理`、`有錯誤`、`疑似重複`。
- 進階篩選放在「更多篩選」面板，不要長期占滿畫面。
- 表格預設只顯示：報名者、單位、報名狀態、會員、付款、問題。
- 點擊整列即可進入詳細資料；不要要求點很小的圖示。
- 欄位空白時顯示 `尚未填寫`，不要只留白。
- 空清單要說明原因，例如「目前沒有待處理的報名」。

## 畫面 2：單筆資料

參考 `02-record-detail.svg`。

- 左上有明確返回 `← 回到名單`。
- 標題顯示姓名與報名編號，不顯示 record id。
- 左側為「原始報名資料（唯讀）」；按個人、聯絡、發票、其他資訊分組。
- 右側為「處理這筆報名」，包含會員、資格、報名狀態、付款狀態與備註。
- 常見流程提供大按鈕：`開始審核`、`通過並等待付款`、`確認完成`；只顯示目前合法的下一步。
- 不符合資格、取消、退款等低頻或高風險動作放在 `其他動作…`，並要求確認。
- 問題提示放在相關欄位附近，頂部另有簡短問題摘要。
- 頁面底部或右側固定顯示 `取消` 與唯一主要按鈕 `儲存變更`。
- 使用者離開有未儲存內容的頁面時要確認。

## 畫面 3：設定與工程介面

參考 `03-advanced-settings.svg`。

一般設定只顯示：

- Google 帳號：已連線／未連線。
- 報名資料：已連線的試算表名稱。
- 來源資料保護：原始回應唯讀。
- `重新連線`、`檢查連線`。

按下 `進階（管理員）` 後再顯示：

- OAuth 用戶端檔。
- Spreadsheet URL／ID。
- 原始回應工作表。
- 管理分頁建立／修復。
- 欄位對應與 schema 健康檢查。
- 診斷包與 log 位置。

進入進階頁時顯示一次短提示：「這些設定通常不需要修改。錯誤設定可能讓系統無法讀取報名資料。」不要使用嚇人的紅色整頁警告。

## 視覺規格

- 沿用 WPF；不要為了外觀把整個專案改成 WinUI。
- 字型：Segoe UI／Microsoft JhengHei UI。
- 內容區最大寬度約 1440；一般邊距 24，區塊間距 16，控制項最小高度 36–40。
- 主色使用單一藍色；紅色只用於真的錯誤或危險動作。
- 卡片使用淡邊框與很輕的陰影；不要大量漸層、玻璃效果或粗重陰影。
- 表格列高至少 44；選取列有淡色背景與左側強調線。
- 主要按鈕每頁最多一個填色按鈕；其他按鈕使用外框或文字樣式。
- 狀態 chip 必須包含文字，避免只用圓點或圖示。

## 防呆與文案

- `同步`改成`更新名單`。
- `Initialize Schema`改成`建立管理資料區`。
- `Conflict`改成`資料已在其他地方更新，請先重新整理`。
- `Validation failed`改成具體動作，例如`聯絡電話尚未填寫`。
- Google 403 改成`目前登入的 Google 帳號沒有這份試算表的編輯權限`。
- Google 404 改成`找不到這份試算表，請檢查連結是否正確`。
- 儲存失敗不得清空已輸入內容。
- 成功訊息採不阻斷的狀態列或 InfoBar，不要每次都跳出 OK 對話框。
- 刪除、取消、退款或覆蓋設定才使用確認對話框。

## 實作界線

- 不修改 Google Form 原始回應頁的唯讀原則。
- 不新增簽到、權限、通知、活動流程、歷史匯入或多活動功能。
- 不在 UI 改版中更動狀態機與 Google Sheet schema。
- `tools/UatHarness` 不是一般使用者功能，不要加入正式 UI。

## 驗收標準

1. 新使用者不看說明，可在 3 分鐘內找到待處理名單並開啟一筆資料。
2. 使用者能分辨原始唯讀資料與可編輯欄位。
3. 從開啟一筆到完成審核不超過 3 個主要操作。
4. 一般模式中不出現任何底線開頭的 Sheet 名稱或英文內部欄位名。
5. 1366×768、100% 與 125% 縮放下不遮住主要按鈕。
6. 鍵盤 Tab 順序合理，Enter 可觸發主要動作，Esc 可取消對話框。
7. 顏色關閉或灰階觀看時，仍能靠文字辨識所有狀態。
8. 未儲存離開、危險狀態轉換、重新建立管理資料區都有清楚確認。
9. 儲存成功、失敗與同步中都有可見但不干擾的狀態提示。
10. 改版前既有 65 個單元測試仍全部通過，並新增 ViewModel／UI 狀態測試。
