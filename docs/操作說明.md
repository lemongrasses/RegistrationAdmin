# 操作說明

開啟程式會自動確認保存的 Google 授權，有效時直接進入後台；未登入、授權失效或確認失敗才顯示 **Google 登入封面**。啟動檢查不會自行開啟瀏覽器。後台分成左側四個入口：**待處理**、**全部名單**、**匯出**、**設定**。Google 帳密只在 Google 網頁輸入，程式目前沒有獨立帳密登入。

需要協助時，按左下角「使用手冊（F1）」或功能附近的「操作說明」。手冊內建在程式中，可離線搜尋章節、閱讀步驟與截圖；開啟說明不會捨棄正在編輯的內容。在主畫面按 F1 會開啟目前頁面的相關章節。

## 一、第一次設定（約 2 分鐘）

> 一般使用者**不需要** Google Cloud 或 OAuth 檔案：程式發佈時已附上 `google-oauth-client.json`。只要有一個「對回應試算表有編輯權限」的 Google 帳號即可。

1. 開啟 RegistrationAdmin。在封面按「登入 Google」，先完成登入，再進行試算表設定：
   - 使用 Windows 預設瀏覽器，程式內目前不能選擇瀏覽器或個人設定檔；不一定與您複製試算表網址時使用的瀏覽器相同。要更換請先到 Windows「設定 → 應用程式 → 預設應用程式」設定，再重新登入。
   - 用有這份試算表編輯權限的帳號登入，按「允許」。
   - 若 Google 顯示其他帳號，選「使用其他帳戶」，改用有權限的帳號。
   - 若瀏覽器登入失敗或已關閉，回到程式按「取消登入」，再按「登入 Google」重試，不需等待逾時或重開程式。
   - 若出現「Google 尚未驗證這個應用程式」，按「進階」→「前往（不安全）」→「允許」。這是內部工具未送 Google 審核的正常提示。
   - 已有有效授權時可直接繼續；程式會向 Google 確認授權有效。若已失效，按封面的「更換帳號／清除保存的登入」後重新登入。
2. 第一次登入後會進入「設定 → 開始使用」。按「選擇試算表…」，在 Google 選擇器中使用相同 Google 帳號選擇有編輯權限的表單回應試算表。選取後會填入網址與檔名；也可直接貼上試算表網址。若開錯帳號、沒有編輯權限或選到 Excel 檔，程式會提示並保留原設定。
3. 按「連線試算表」，確認 Google 帳號與報名資料。之後開啟，有效授權會自動跳過封面並連線已設定的試算表；網路確認失敗時可在封面重試。
4. 若試算表只有一張回應分頁，程式會詢問是否「建立管理資料區」，按「建立管理資料區」。**程式不會修改原始回應頁**。有多張分頁時，打開「進階（管理員）」，在「原始回應工作表」選擇表單回應分頁後按「建立管理資料區」。
5. 建立後會自動更新名單並檢查報名表欄位。若「資料保護」顯示欄位對不上，代表回應頁的題目標題與 `_FieldMap` 的 `source_header` 不一致：
   到試算表的 `_FieldMap` 把該列 `source_header` 改成回應頁的實際標題（可用 `|` 列出多個允許的標題；前後空白會自動忽略），再回程式按「更新名單」。

要換帳號：「設定」→「重新連線」，返回封面按「登入 Google」，再在瀏覽器選擇其他帳號。登出會清除記憶體中的名單；有未儲存的變更時會先詢問。

要換試算表：在「設定」按「選擇試算表…」。選取不同檔案後會清除舊名單，按「連線試算表」後才讀取新名單。等待選擇器時可「取消選擇」後立即重試；取消或失敗會保留原設定。選取本身不寫入管理分頁。

維護者須在同一個 Google Cloud 專案啟用 **Google Picker API** 與 **Google Drive API**。選擇器另外要求 `drive.file` 權限，不會覆蓋原本的 Sheets 登入，也不要求整個 Drive 的讀取權限；臨時 token 不保存在電腦上。選擇器無法使用時仍可貼網址連線。

> 建議：用一個「只被分享這份回應試算表」的專用 Google 帳號登入，讓 Google 端的權限也只涵蓋這份檔案。

### 維護人員：建立隨程式發佈的 OAuth 用戶端（整個組織只做一次）

1. Google Cloud Console 建立（或選擇）專案，「API 和服務 → 程式庫」啟用 **Google Sheets API**。
2. 「OAuth 同意畫面」：使用者類型選「外部」，填應用程式名稱。
   - 發布狀態選「**正式版（In production）**」：使用者第一次登入會看到「未驗證」提示，按「繼續」即可；登入長期有效。
   - 若維持「測試」狀態：只有加入「測試使用者」的帳號能登入，且 Google 每 7 天會要求重新登入。
3. 「憑證 → 建立憑證 → OAuth 用戶端 ID」，類型選 **電腦版應用程式（Desktop app）**，下載 JSON。
4. 把 JSON 複製為專案的 `config\google-oauth-client.json`，建置或執行 `scripts\publish.ps1` 時會自動放到 exe 旁。此檔已列入 `.gitignore`，**不要提交到版控**。
5. 臨時改用其他用戶端檔：「設定 → 進階（管理員）→ OAuth 用戶端檔」。

## 二、日常操作

| 要做的事 | 操作 |
|---|---|
| 讀取最新報名 | 右上角「更新名單」（F5）。新回應只會建立一次後台資料。 |
| 看今天要處理什麼 | 左側「待處理」：列出尚未審核、等待付款核帳、資料有錯誤或疑似重複的報名；上方四張卡是全部、待審核、待付款、已確認的數量。 |
| 找人 | 大搜尋框（Ctrl+F）可搜尋姓名、Email、電話、單位或報名編號。下方籤可切換「待處理／全部／有錯誤／疑似重複」；其他條件在「更多篩選」。點欄位標題可排序。 |
| 開啟一筆 | 點整列，或用方向鍵選取後按 Enter。左側是**原始報名資料（唯讀）**，右側是**處理這筆報名**。 |
| 審核 | 右側按藍色大按鈕：「確認會員並開始審核」→「通過並等待付款」。每按一次，上方會列出「按儲存變更後會更新」的內容；確認後按右上角「儲存變更」（Ctrl+S）。 |
| 付款核帳 | 狀態為「通過待付款」時按「確認已付款，完成報名」（付款與核帳日期未填時填入今天），或在「4　付款」逐欄填寫，再儲存。 |
| 不通過、候補、取消、退款、封存 | 「其他動作…」。每個動作都會再確認；不通過與取消需要填寫理由。 |
| 修正錯字 | 右側最下方「修正報名者資料」填正確值；原始答案不變，畫面與匯出採用修正值。清空即恢復原始答案。 |
| 處理問題 | 頁面上方會列出這筆有幾項需要處理；右側「需要確認的問題」可按「確認沒問題…」並填寫原因。 |
| 回到名單 | 左上角「← 回到名單」（Alt+←）。有尚未儲存的變更時會先詢問。 |
| 匯出 | 左側「匯出」：選擇用途（全部、待審核、通過待付款、已確認、候補、付款核對、發票、午餐）、範圍（全部或目前名單的篩選結果）與格式，按「匯出…」。 |

儲存成功、失敗與更新中的訊息會出現在畫面下方，不會跳出需要按「確定」的視窗；成功訊息數秒後自動消失。

### 狀態流程

```
新報名 → 審核中 → 通過待付款 → 已確認
                 ├→ 候補 → 通過待付款
                 └→ 不通過（需填理由）
通過待付款 → 付款逾期／已取消（需填原因）
```

- 「通過並等待付款」前必須：會員「已確認會員」、資格「符合資格」（按鈕會把「未核對／未判定」一併設好）、四項確認都有勾選、姓名／單位／職稱／Email／電話／發票抬頭／統編／午餐不缺，且名額未滿。條件不符時按鈕不會改變任何資料，並在右側列出原因。
- 「通過待付款」與「已確認」占用 20 人名額；名額滿時只能保持審核中或轉候補。
- 系統不會自動轉換狀態、不寄信、不建立金流交易。

## 三、重要規則

- **同一時間只由一位主要管理者修改後台資料。** 若儲存時出現「資料已在其他地方更新，請先按「更新名單」重新整理」，請照做後再修改；程式不會覆寫別人的修改。
- 不要在原始回應頁排序、改標題、刪列或改答案。若報名者修改過答案，詳細頁會顯示「報名者修改過原始答案」，確認後按「我已確認最新內容」。
- 網路中斷時儲存會失敗，輸入內容保留在畫面上，恢復網路後再按一次「儲存變更」。
- 測試請使用**複製的測試表單與試算表**，不要對正式表單送出測試資料。

## 四、問題排除

| 訊息 | 處理 |
|---|---|
| 找不到 Google 登入設定檔 | 程式資料夾缺少 `google-oauth-client.json`：請向維護人員索取完整安裝包，或在「設定 → 進階（管理員）」選擇 JSON 檔。 |
| 目前登入的 Google 帳號沒有這份試算表的編輯權限 | 請試算表擁有者分享「編輯者」權限，或按「重新連線」改用有權限的帳號。 |
| 找不到這份試算表 | 試算表網址錯誤，或檔案已刪除。到「設定 → 進階（管理員）」修正網址。 |
| 報名表的欄位和系統設定對不上 | 修改 `_FieldMap` 的 `source_header`（見第一節第 5 步）；「進階（管理員）→ 顯示欄位檢查結果」會列出缺少的欄位。 |
| 管理分頁缺少欄位 | 「設定 → 進階（管理員）」→「建立管理資料區」會在最後補上缺少的欄位。 |
| Google 目前太忙碌 | 程式已自動等待並重試約 90 秒仍失敗；稍候 1 分鐘再按一次儲存，輸入內容仍保留在畫面上。 |
| 原始資料與後台資料的對應有問題 | 「設定 → 進階（管理員）→ 原始資料與後台資料的對應」選擇原始回應與後台資料後按「重新連結」。 |
| 需要回報問題 | 「設定 → 進階（管理員）」→「建立診斷資料…」，把 zip 交給維護人員。診斷資料不含 token、Spreadsheet ID 或報名資料，日誌已遮蔽個資。 |

本機檔案位置：`%LOCALAPPDATA%\RegistrationAdmin\`（`settings.json`、`tokens\` 加密授權、`logs\` 保留 14 天）。
